# Sprint 1 Implementation Plan

**Goal:** Build the approved browser-only investigation interface and a configuration-ready authenticated fixture-to-report vertical slice.

**Architecture:** Next.js on Vercel calls authenticated Fastify on Render. Supabase validates identity and persists private runs/events/evidence/reports. Gemini BYOK analyzes collected evidence. Public arbitrary-URL runs remain disabled while Sprint 0's deployed isolation gate is unresolved.

**Tech stack:** TypeScript/pnpm, Next.js/React, Fastify/Playwright, Supabase, Gemini REST adapter with bounded structured output.

## Delivery boundaries

- User authorized continuation of approved sprints. No further design checkpoint required for agreed screens.
- No Marten Supabase project is connected; unrelated existing projects must not be changed. Prepare schema/config locally, never claim live OAuth/database verification without credentials.
- Real fixture mode must be visibly labeled. A public example report may use explicit sample content; never fake investigation events or silently substitute fixture results for an entered target.
- Final mascot pose set remains Sprint 3; create one approved-style soft-3D marten asset for this initial interface if image generation is available.

## Task 1 — Backend and shared contracts

Owner: backend/AI specialist. Own apps/api, packages/contracts, supabase schema files, root dependencies/config.

1. Define plain shared TypeScript contracts: Investigation, Event, Evidence, Report/Finding; status and error codes. Expose GET /v1/investigations, POST /v1/investigations, GET /v1/investigations/:id, GET /v1/investigations/:id/events?after=, POST /v1/investigations/:id/cancel, GET /v1/investigations/:id/evidence/:evidenceId, DELETE /v1/investigations/:id.
2. POST body: { targetUrl, brief?, apiKey, mode: 'fixture' }. Require authenticated identity; reject non-fixture mode and arbitrary URLs explicitly. Use a reserved fixed fixture identifier agreed with frontend.
3. Implement repository interface, memory implementation only for tests, and Supabase-backed production configuration. Fail closed when unconfigured. Ownership and expiry enforced on reads and mutation.
4. Integrate current collector with durable per-page/event persistence before publication; serialize one run, cancellation/timeout, safe error handling, stale-run reconciliation. API keys only in transient run scope, never logs/repository/errors.
5. Gemini adapter uses fixed endpoint, bounded timeout/output and response validation; evidence references verified. No automatic paid fallback. Quota errors preserve partial evidence.
6. Tests first for identity/ownership, invalid scope, quota/busy, cancellation, partial results, invented evidence, and key redaction. Preserve Sprint 0 tests.
7. Prepare SQL schema/private bucket/RLS plus configuration instructions, using Supabase skill. Do not touch remote projects.

## Task 2 — Frontend

Owner: frontend/UX specialist. Own apps/web and DESIGN.md only; coordinate dependency changes with backend owner.

1. Read approved product/UX and Impeccable craft guidance. Build responsive dark brown/ivory/amber interface: landing, auth, dashboard/start, run workspace and report/history.
2. Supabase Google/GitHub OAuth using configured public env; preserve non-secret inputs across redirect. No fake login or persisted API key.
3. Connect typed API client using bearer token and incremental polling; preserve inspected evidence selection while new events arrive. State labels reflect backend, not invented percentages.
4. Explicit fixture mode while public runs unavailable. Unconfigured integrations display honest actionable state. Public labeled sample report is usable without sign-in.
5. Evidence selection, report citations, coverage/limitations, cancellation, deletion, provider errors, keyboard and narrow-screen support.
6. Build/typecheck and bounded desktop/mobile browser review. Do not simulate successful live AI/OAuth calls.

## Task 3 — Review and verification

Owner: independent security/testing specialist, then orchestrator.

Review spec and code quality; fix material issues. Run backend test suite, typecheck, frontend production build, controlled browser flow/screenshots. Record separately what is tested with fixtures/mocks and what requires real Supabase OAuth/Gemini credentials or cloud hosting. Keep all cloud accounts unchanged. Save a local Git checkpoint after verification.
