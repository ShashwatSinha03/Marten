# Sprint 0 Implementation Plan

> Execute with specialist subagents in this session, following test-driven-development and independent spec/quality review.

**Goal:** Produce a reproducible, controlled-fixture browser feasibility harness and measured go/no-go evidence for the selected hosting.

**Architecture:** Node/TypeScript collector with Playwright, typed evidence/events, bounded run lifecycle, and a controlled fixture. Arbitrary public URLs stay disabled until deployed sandbox/egress checks pass.

**Tech Stack:** pnpm workspace, TypeScript, Playwright, Node test runner or Vitest, Fastify only as needed for health/probe hosting. No frontend/auth/AI implementation until the runtime is established.

## Task 1 — Reproducible collector feasibility harness

Owner: backend/browser specialist.

Create root package/workspace/TypeScript configuration, `apps/api/src` collector/fixture/storage/probe modules and `apps/api/test` behavioral tests. Exact module layout may be kept small rather than scaffolding future features.

1. Pin current compatible dependencies and lockfile; provide `pnpm test`, `pnpm typecheck`, `pnpm probe` commands.
2. Write and run failing tests for page caps, fixture-only origin policy, evidence references, timeout/cancellation, and partial evidence persistence before implementation.
3. Implement a controlled fixture containing healthy navigation, a 404, and a hanging response. Start it on ephemeral loopback only for the internal probe. No user-controlled URL endpoint.
4. Implement fresh sandbox-enabled browser collection with screenshots, URLs/status/timestamps, bounded text/links, append-only persisted events, manifest, and measured process-tree memory where available. Report measurement limitations explicitly.
5. Enforce duration/page caps and close browser resources in all terminal paths. The fixture exception must not become a public-mode bypass.
6. Run a real probe and meaningful browser integration tests. If browser launch is sandbox-blocked, request narrowly scoped tool escalation; never silently disable Chromium sandbox.
7. Write a minimal health-only hosting entrypoint and non-root Docker/Render configuration where useful for deploy verification. Do not expose an unauthenticated investigation trigger or claim deployment success.

Acceptance: real screenshot plus persisted evidence/events from seeded fixtures; healthy versus 404 distinction; cancellation/deadline tests; local measurements; no arbitrary-site execution surface.
